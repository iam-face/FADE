# Production dedicated server - testing tracker

**Purpose:** Log issues found after deploying this scenario to the **production dedicated server**, track severity and status, and outline a **plan** for fixes without implementing them in this document.

**Environment:** Production dedicated server (post-upload initial testing).

---

## Legend


| Field        | Meaning                                                                                                                                                                                                           |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Severity** | **Blocker** - session broken or major feature unusable; **High** - common path wrong or sync risk; **Medium** - workaround exists or edge case; **Low** - cosmetic, rare, or polish                               |
| **Status**   | **Open** - not fixed; **Investigating** - cause unclear; **Planned** - fix approach agreed; **Verified** - fixed and re-tested on server; **Retracted** - report incorrect or no longer applicable; no fix needed |

## Planning

- **Triage:** Confirm reproduction on the production server; note client vs server, JIP vs initial join, and required mods/keys.
- **Order of work:** Address blockers and high-severity sync or mission-flow issues first; then medium; batch low-severity items when convenient.
- **Verification:** After each fix, re-test the same path on the production dedicated server and update **Status** in the table above.
